# 中国流动性温度计 · V0 原型

> **这是一个未经校准的研究原型，不是一个可用的投资决策工具。**
> 页面上的分数由经验系数算出，系数尚未经过统计检验；「状态 → 大盘表现」是同步统计而非预测，当前样本只有 1 天。请勿据此交易。

把央行公开市场操作、银行间资金利率和 A 股成交额，翻译成一句普通人能看懂的话：

> 今日流动性：41 / 100 ｜ 中性

产品上的取舍是**结论先行**：首页只给结论和一句人话解释，点开「为什么」才展开四层拆解。所有计算都在单个 HTML 文件里，透明、可逐行检查。

## 快速开始

不需要安装任何依赖，也不需要服务器。

```bash
# 1. 直接双击 dist/online.html 就能看（数据已内联，离线可用）
# 2. 改过 data.js 或页面后，重新生成发布文件
node build-online.js
# 3. 跑回归测试
npm test
```

需要 Node.js 18+。**没有 npm 依赖包**，`package.json` 只是把常用命令收拢成一个入口。

| 命令 | 作用 |
|---|---|
| `npm run build` | 把 `data.js` 内联进源码，生成 `dist/` 三件套 |
| `npm test` | 在模拟浏览器环境里真跑页面逻辑，全套回归 |
| `npm run check` | 离线自检数据文件结构与评分一致性（不联网） |
| `npm run update` | 拉取行情并更新 `data.js`（见下文「自己更新数据」） |

## 文件结构：哪个才是入口

| 文件 | 角色 |
|---|---|
| `liquidity-dashboard.html` | **开发入口**。全部 HTML/CSS/JS，读取同目录 `data.js` |
| `data.js` | 数据快照：`window.PBEC_DATA`，含历史与统计样本 |
| `dist/online.html` | **分发入口**。自包含单文件，可直接双击或静态托管 |
| `dist/index.html` + `dist/data.js` | 部署副本（页面与数据分开） |
| `build-online.js` | 从上面两个源文件生成 `dist/` 全部内容 |
| `verify-online.js` | 回归测试 |
| `scripts/update-data.mjs` | 独立数据更新脚本 |
| `docs/data-and-methodology.md` | 字段规范、评分公式、已知未校准项 |

> **不要直接编辑 `dist/`**：它由 `build-online.js` 生成，CI 会检查构建结果可复现。改源码后跑一次 `npm run build`。

## 它怎么算

总分 0–100，越高越宽松，四模块加权：

```
操作分   = clamp(15 + 近 5 日累计净投放 / 600, 0, 30)
价格分   = clamp(20 - (DR007 - (政策利率 + 期限溢价 10bp)) * 100, 0, 40)
趋势分   = clamp(10 - (chg007 + chg001) / 4, 0, 20)
特殊因素 = 5 + 日历扰动调整
```

默认权重 `30 / 40 / 20 / 10`；可切换「价格优先」`15 / 50 / 25 / 10`，两种口径的归档样本分开保存，不混进同一条曲线。

判定档位（页面显示）：`80+` 明显宽松 · `60–79` 偏松 · `40–59` 中性 · `20–39` 偏紧 · `<20` 明显偏紧。统计器另按三态分组（宽松 / 中性 / 偏紧）。

字段定义与完整公式见 [`docs/data-and-methodology.md`](docs/data-and-methodology.md)。

## 自己更新数据

数据分两类，**自动与手工必须分开看待**：

| 字段组 | 方式 |
|---|---|
| A 股成交额、指数涨跌、主力资金净流入 | `npm run update` 从公开行情接口拉取 |
| 央行操作流水、政策利率、DR001/DR007、R001/R007、日历扰动 | 填 `data/manual-input.json`（复制自 `.example.json`），脚本合并 |

央行公告与银行间利率没有稳定的开放 API，本项目**不假装有全自动抓取**。脚本会：

- 复用页面自身的 `computeScore()` 计算分数，不引入第二套实现
- 对成交额、涨跌幅、资金流做合理区间护栏，异常值直接拒绝写入并报错
- 保留 `history` / `marketStats` 已有条目，按日期去重、限制条数
- 给同一天的数据 `rev` +1，让页面强制重新采纳
- 支持 `--dry-run`（只打印不写）和 `--offline --check`（不联网的结构自检）

```bash
cp data/manual-input.example.json data/manual-input.json
# 编辑后
npm run update -- --dry-run
npm run update
npm run build      # 把新 data.js 重新内联进 dist/，否则页面仍是旧快照
```

`npm run update` 只会写 `data.js`；分发用的 `dist/online.html` 是构建产物，**必须再跑一次 `npm run build`**（或 push 让 CI 构建、重新部署）才会带上新数据。CI 的 `update-data.yml` 已包含这一步。

脚本要求 `manual-input.json` 里有当天的 `policyRate / dr001 / dr007` 与当日 `ops`；缺录入、或 `--date` 指定的不是当天时，会直接中止且不写任何文件（行情接口也取不到历史行情）。页面同样只在「数据快照日期 = 本机日期」时才生成当日归档，断更时照常显示结论，但不会把旧数据记成当天。

`manual-input.json` 含个人填写的数据，已加入 `.gitignore`。

## 已知局限

1. **系数未经校准**：「每 600 亿 ≈ 1 分」「期限溢价 10bp」都是经验设定，需要数周真实数据回看。
2. **操作分接近开关**：固定分母使净投放到约 ±9000 亿即触顶，多数交易日该模块区分度很低；价格优先口径下同一组数据分数明显不同，说明数量口径可能系统性低估宽松程度。
3. **锚点是自己设的**：`termPremium` 会直接改变判定档位，并非市场实测值。
4. **历史曲线不可直接比较**：`history` 中 `estimate:true` 的分数是用当前模型回算的，与当时实算值混在一条线上。
5. **统计器不是预测**：流动性状态与当日大盘表现互为镜像，相关性 ≠ 因果；样本少于 5 天的状态组不给出结论。当前只有 1 条样本，且是盘中快照。
6. **归档分散在各浏览器**：页面自动生成的样本存在 `localStorage`，不同访客看到的累计样本不同；权威样本始终来自 `data.js`。
7. **无服务端、无回测框架**：这是纯前端原型，实时行情靠浏览器侧 JSONP，失败时回退到快照或手工输入。

## CI

`.github/workflows/ci.yml` 在每次 push 时：重新构建 → 跑全套回归 → 离线数据自检 → 检查 `dist/` 与提交内容一致（构建可复现）→ 部署到 GitHub Pages。首次使用需在仓库 Settings → Pages 里把 source 设为 **GitHub Actions**。
