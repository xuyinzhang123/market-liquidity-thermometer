# 自动更新的实际口径

2026-11-09 起，`scripts/auto-liquidity.py` 用 Python 标准库读取人民银行公告和中国货币网公开文件，无密钥、无付费 AI。评分调用页面自身 `computeScore()`，权重及公式没有另写一套。

## 来源与日期

- 央行常规质押逆回购公告：[官方列表](https://www.pbc.gov.cn/zhengcehuobisi/125207/125213/125431/125475/index.html)。核对公告日与正文操作日，读取中标量（不是投标量），支持零投放和正文中的隔夜操作。
- DR001/DR007：[中国货币网公开加权利率](https://www.chinamoney.com.cn/r/cms/www/chinamoney/data/currency/prr-md.json)。使用 `weightedRate`，不使用最新成交价 `latestRate`，也不使用 FDR/FR 定盘利率替代。
- 五交易日趋势：[同源历史序列](https://www.chinamoney.com.cn/r/cms/www/chinamoney/data/currency/prr-chrt.csv)，按官网图表的第 7、8 列读取 DR001/DR007，与五个交易日前的值相减乘100，单位bp。
- 只把同一操作日的公告与利率组成评分。上午当天利率没发布时，保留最近一个完整快照，另外发布最新公告日期和等待原因。盘中利率标明时间和“盘中”，17:00及之后标为“日终”。这不是对未来交易时段的预测。

## 有意限定的范围

自动模式 `auto-repo-v1` 的操作流水仅包括**常规质押逆回购**，不是央行全部工具的净投放。买断式逆回购、MLF、国库现金定存、国债买卖不自动混入，也不沿用旧流水。页面明确说明这个范围。

从最近20篇常规操作公告回溯投放，按公告期限计算到期量；非操作日顺延到下个已观察到的央行操作日。使用最近五个操作日，且与DR历史交易日交叉检查。缺公告、未知格式、28/63天等超出已验证回溯区间的操作会中止，不猜测到期量。该规则对调休/节假日保持保守；遇到特殊结算安排需维护解析器。

R001/R007取不到时为 `null`，页面显示未取得并暂停非银分层判断；R不参与当前公式。不会拿旧值或DR替代R。

日历模块仍是模型假设：每月14–18日为税期，月/季末最后4个自然日为跨期窗口；春节、政府债与财政因素未自动判定，取中性。它们不代表已核验的实际资金收支，页面会注明。`termPremium`仍为原先10bp经验参数。

自动模式与早期手工演示快照口径不同。历史/统计按 `date|mode|method` 隔离，避免连成可比曲线；旧记录留在源数据供审计。自动归档两个权重模式的评分，没有同日市场表现时对应字段留空，不和其他日期行情配对。

## 发布与故障

工作流北京时间工作日09:25、10:30、11:45、17:20运行，另每天16:30、18:23运行；GitHub计划任务会延迟，不保证9:25准点。

采集 → 数据校验 → 复用页面评分 → 归档 → 构建 → 回归 → commit → 同一工作流部署Pages。行情和评分采集独立：一个源失败不阻止另一个源更新，失败最后会让工作流报红。最近有效评分不被半成品覆盖。

`data/collection-status.json` 记录等待/错误，构建时复制到 `dist/`。`dist/latest.json` 是页面打开时读取的统一JSON数据源；GitHub、扣子和本地单文件副本可以读取相同的最新快照，失败时保留内联数据和真实日期，不执行远程JavaScript。

本地运行：`python scripts/auto-liquidity.py --dry-run` 只检查；去掉参数写入，随后 `npm run build`、`npm test`、`npm run check`。Node>=18、Python>=3.10。公开页面和文件无SLA，结构或政策机制变化需要维护，不承诺永久无人值守。
